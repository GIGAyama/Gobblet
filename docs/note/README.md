# note 入稿メモ（パクパクゴブレット）

このフォルダの中身は、note の連載「教室で使えるかもしれないもの作り」に載せる
紹介記事一式です。

```
docs/note/
├── gobblet-note-article.md   記事本文。そのまま note に貼れる形
├── images/                   実際にブラウザを操作して撮った画面 22枚
└── README.md                 このファイル
```

## 貼るまえに直すところ

- **連載番号**。本文1行目の見出しが `#◯` のままです。何回目かは分からなかったので
  埋めていません。ここだけ書き換えてください。
- 前作の紹介記事がすでにある場合は、「🏫 はじめに」の最後あたりに
  「以前この連載で紹介した◯◯の続きです」といった一文を足すと、連載の読者に
  記事の位置づけが伝わります。今回は前作が確認できなかったので入れていません。

## note に貼る手順

1. note で新規記事を作り、記事本文の1行目（`# 教室で使えるかもしれないもの作り …`）を
   タイトル欄に貼ります。本文側からは消します。
2. 残りの本文をそのまま貼ります。Markdown は見出し（`##`）と番号つきリストだけなので、
   note のエディタでそのまま見出しとリストになります。
3. 画像は自動では入らないので、`images/` から手で1枚ずつアップロードします。
   本文中の `![…](images/xx-….png)` の位置と順番はそのまま対応しています。
   貼り終えたら `![…](…)` の行は消してください。
4. 画像の下に置いてある一文は、note のキャプション欄に移します。
5. ハッシュタグは `#GIGAスクール` `#ICT教育` `#小学校` `#プログラミング` `#PWA` あたりを
   想定しています。連載でいつも付けているものに合わせてください。

## 記事に書いた数字の出どころ

README にあった数字をそのまま写さず、コードとファイルサイズで裏を取り直しました。
一つ、README の記述と食いちがうものがあります。

- **43キロバイト（最初の画面が出るまで）／103キロバイト（全部あわせて）**
  `index.html` `js/pwa-install.js` `css/style.css` `js/rules.js` `js/furigana.js`
  `js/app.js` `manifest.webmanifest` `icon.svg` の合計が 44,119 バイト。
  `sw.js` の `PRECACHE_URLS` に並ぶ17ファイルの合計が 104,765 バイト。
  `npm run check` の F5（総アセット 102.3KB）とも一致します。
  リポジトリの `README.md` には「初回に読み込むファイルは合計 60KB 程度」とありますが、
  実測とは合いません。記事には実測のほうを書いています。README のほうも直すと
  食いちがいがなくなります。
- **40人で4メガバイト** 104,765 バイト × 40 = 約4.0MB。
- **駒は1人6つ、2人で12個** `js/app.js` の `makeHand` が `[0,0,1,1,2,2]`。
  大中小それぞれ2つずつです。
- **そろえ方は8通り** `js/rules.js` の `LINES` が8本。
  `tests/rules.test.mjs` の「勝ち筋は8通りすべてが定義されている」で検証済みです。
- **1回2分から5分** `MANUAL.md` の「かかる時間」から。実測ではありません。
- **横320pxではみ出さない** 撮影中に
  `document.documentElement.scrollWidth - window.innerWidth` を測って 0 を確認。
- **許可するアドレスは gigayama.github.io の1つだけ**
  `index.html` の CSP が `connect-src 'self'` で、外部への通信先がありません。
- **端末に何も残らない** `localStorage` を使っている箇所がリポジトリ全体にありません。

## 撮影について

`playwright` で実際に Chromium を動かし、ボタンを文字で押して撮りました。
配信は本番と同じ `/Gobblet/` の下で行っています。ルート直下で配ると
Service Worker と manifest の挙動が本番と変わるためです。

撮り直すときの手順です。

1. `npm i --no-save playwright`
2. リポジトリの中身を作業用のフォルダにコピーし、`/Gobblet/` の下で配信する
   静的サーバを立てます（note-article スキルの `scripts/serve.mjs` を使いました）。
3. 撮影シナリオを書いて `scripts/capture.mjs` に渡します。今回のシナリオは
   `.tmp-shots/shots.mjs` に置いて、納品時に削除しました。

撮るときに引っかかった点を3つ残しておきます。

- Service Worker が最初に有効になるとき、アプリは1回だけページを読み込み直します。
  これが対局の途中で起きると盤が消えるので、撮りはじめる前に
  `navigator.serviceWorker.controller` が入るまで待つ必要があります。
- 勝ったときのお祝いが、そろった3マスを隠してしまいます。「もう一回」を押すと
  盤がリセットされてしまうので、Escape キーでお祝いだけ閉じて撮り直しました。
- ボタンの文字にはふりがなの `<ruby>` が混ざっているので、`textContent` で
  そのまま照合すると「やり直す」が「やり直なおす」になって当たりません。
  `<rt>` と `<rp>` を落としてから比べています。

## 動作の確認について

記事に書いた機能は、すべて実際に画面を操作して動くことを確かめました。
壊れている機能は見つかりませんでした。あわせて次も通っています。

- `npm test` 19件すべて成功

## 文体について

`references/style.md` の指定に沿って書きました。踏襲したのは次の点です。

- 太字、斜体、表、`→` `／` `▲` `▶` `：` を本文で使っていません（0件を機械的に確認済み）
- Markdown は見出しと、手順の番号つきリストだけです
- 箇条書きは「導入手順」と「使い方のガイド」の手順部分だけに絞りました
- 絵文字は見出しにだけ置いています
- デプロイ、キャッシュ、ローカルストレージ、CSP といった言葉は本文に出していません。
  「公開の設定」「端末のなかに何も書き残さない」などに言いかえています
- 子どものことは「子どもたち」、読み手は「先生」「先生方」で通しています
- 教室での出来事を実体験としては書いていません。「こうなればいいと思って作った」
  「〜だと思います」までにとどめてあります。実際の授業での様子は、
  書き手が自分で足すところとして空けてあります
- 見出しは基本の6本に、目玉のために2本だけ足しました
  （🧠 3つ並べるだけなのに、最後の一手でひっくり返る／🔤 画面の漢字に、ひとつ残らずふりがなを付けました）

本文の字数は約7,600字です（画像の記法をのぞいた数）。
